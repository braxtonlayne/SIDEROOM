# Arena 3D: SIDE ROOM's 3D starter kit (`ACT-A3D-001`)

A small, complete, multiplayer low-poly 3D game that runs as a SIDE ROOM Activity, written to be copied. Walk,
jump, crouch, shove boxes onto the green pad, see the other players. Underneath it is the template for SIDE ROOM's
3D games: a deterministic Jolt Physics simulation, host-authoritative networking with client-side prediction over
the SDK's data channel, a WebGPU renderer with a WebGL2 fallback, a glTF loader, and a replay harness that proves
the simulation is deterministic.

No third-party code besides Jolt Physics (MIT, `jolt-physics` 1.1.1, pinned) and SIDE ROOM's own Embedded App
SDK. No engine, no math library, no build step in the bundle. See `NOTICE.md` for provenance.

## Running it

From the repository root (pnpm is `npx pnpm@10.12.1` with `npm_config_manage_package_manager_versions=false`):

```sh
pnpm --filter @sideroom/activity-arena3d test        # vitest: determinism gate, netcode, codec, render, assets, bundle, guest path
```

From this folder:

```sh
npx tsc --noEmit -p tsconfig.json   # typecheck (checkJs, strict)
node tools/bundle.mjs               # build dist/ and check it against SIDE ROOM's bundle rules and CSP
node replay/run-node.mjs            # the replay's state hashes in Node
```

**Play locally:** serve `dist/` with any static file server and open `index.html?user=alice` and
`index.html?user=bob` in two tabs of the same browser. Outside SIDE ROOM the fake platform takes over: the tabs
find each other over a `BroadcastChannel` and the first one hosts. Add `&instance=room2` for a separate room.

**Check determinism in a browser:** open `dist/replay/replay.html`. It runs the recorded script and prints the
final hash in `<output id="hash">` (its `data-state` turns `done`). Every browser must print the same hash as
`node replay/run-node.mjs`.

## What each module does

| Folder | What it is |
|---|---|
| `sim/` | The deterministic simulation. No DOM, no clock, runs in Node and the browser. `world.js` is the Jolt world (static level, capsule `CharacterVirtual` players with move/jump/crouch, dynamic boxes), the 60 Hz `step()`, `stateHash()`, `snapshot()`/`applySnapshot()`. `level.js` is the arena as data. `rng.js` is the seeded PRNG, `dmath.js` deterministic sin/cos, `input.js` the integer input format, `input-log.js` the input log, `hash.js` the state hasher, `jolt-loader.js` the lazy browser loader. |
| `net/` | Networking. `codec.js` is the versioned binary wire format. `host.js` runs the authority. `client.js` is prediction and reconciliation. `interp.js` interpolates remote players. `handoff.js` and `seats.js` move the host (D-388). `channel.js` defines the transport seam: `sdk-channel.js` (SIDE ROOM), `bc-channel.js` (browser tabs), `loopback.js` (tests, with seeded latency/jitter/loss). |
| `render/` | `renderer.js` picks WebGPU or WebGL2 behind one interface and rebuilds it after a GPU loss. `webgpu.js` and `webgl2.js` are the backends, and `shaders.js` holds the one program in WGSL and GLSL. `meshes.js` has the procedural low-poly meshes and `math.js` the mat4/vec3/quat helpers. |
| `assets/` | `source.js`: the `AssetSource` interface, `BundledAssetSource` (relative URLs) and `ShelfAssetSource` (a member's shelf, `byos_read`). `gltf.js`: a minimal glTF 2.0 loader. `models/beacon.json`: the sample model, generated by `make-beacon.mjs`. |
| `client/` | The demo page: `index.html` (menu, settings, how-to), `main.js` (boot), `game.js` (loop), `input.js` (keys, pointer lock), `touch.js` (phone controls), `pacer.js` (how many ticks are due), `scene.js` (draw list), `hud.js`, `sfx.js` (synthesised sound), `settings.js` (saved through storage), `spatial-voice.js` (voice hooks). |
| `platform/` | `sideroom-platform.js` (the SDK; guest-safe), `fake-platform.js` (local development), `platform.js` (the choice). |
| `replay/` | `script.js` (the recorded input script: 900 ticks, 2 players; generated by `make-script.mjs`), `run.js` (the runner shared by Node and the browser), `replay.html` (the browser page), `run-node.mjs`. |
| `tools/bundle.mjs` | Builds `dist/` with Land.io's bundle checks, unchanged. It vendors the SDK and Jolt. |
| `test/` | Vitest, Node only. |

## Determinism (the rules the simulation keeps)

Every client runs the same simulation, so the same inputs must give the same state everywhere:

- **Fixed step:** `World.step()` always advances `1/60` s and an integer `tick`. The page's clock decides *when*
  to step (`client/game.js`), never *how much*.
- **Integer inputs:** buttons are a bit set, look is an integer yaw/pitch (65536 units per turn). Mouse deltas are
  accumulated outside the sim, and only the rounded integers go in.
- **No engine math the spec leaves open:** `Math.sin`/`Math.cos` differ between JS engines, so the sim turns yaw
  into a direction with `sim/dmath.js` (exact quadrant split plus a fixed polynomial: only `+ - * /`, which IEEE-754
  pins down). `Math.sqrt` is correctly rounded and fine.
- **One seeded PRNG:** `sim/rng.js` (mulberry32). Its state is in the snapshot and the hash. `Math.random()` never
  appears in `sim/`.
- **No wall-clock time** in `sim/`.
- **Stable order:** statics, then boxes, then players by slot are created, added and stepped in that order. The
  module-wide CharacterID counter is reset per world.

**The gate:** `test/replay.test.js` runs `replay/script.js` in two separate Jolt module instances (two WASM heaps)
and requires the identical hash at every 60th tick and at the end, both the quantised hash and the float32-exact
one. The npm Jolt build is not compiled with Jolt's `CROSS_PLATFORM_DETERMINISTIC` switch. Every browser runs the
same `.wasm`, so results should still agree, and `replay/replay.html` is how each browser is checked. If browsers
ever disagree, don't work around it: the fix is a self-built Jolt with that switch, which needs the owner's yes.

## Networking

- **The host is the authority.** The host is the member who launched the instance (`sdk.isHost`), and it runs the
  only simulation that counts.
- **Peers send inputs, not state.** Every 2 ticks a peer sends all of its unacknowledged input frames (up to 32) with
  `sdk.input.send`. Sending them all again is deliberate: a lost packet is covered by the next one.
- **The host applies at most one queued input per peer per tick,** in slot order. An empty queue repeats the last
  input, and a backlog over 8 is trimmed. Every 3 ticks (20 Hz) the host publishes a snapshot with
  `sdk.state.set({ 'host:snap': base64 })`: every body and player, as float32 (lossless, since Jolt stores
  float32), plus the seq of the last input it applied for each slot. A typical snapshot is under 1 KiB.
- **Peers predict and reconcile.** A peer applies its own input at once. When a snapshot arrives, it drops the
  acknowledged inputs, rewinds its world to the snapshot (`applySnapshot`) and re-simulates the rest. The
  difference becomes a visual offset that decays over a few frames.
- **Remote players are interpolated** about 100 ms in the past (`net/interp.js`).
- **Who plays comes from HELLO messages, not from the platform.** Peers that go silent for 10 s or send BYE are
  removed, so the host needs no participant list. That is what makes the game work for guests.

The loopback tests run this with 60–90 ms one-way latency and 10–20 % loss. They check that the peer's predicted
position ends up within 1 cm of the host's (the recorded run lands exactly on it).

### Host migration (`host_handoff`, D-388)

`sideroom.json` declares `host_handoff`: when the host's page goes away, the platform names the longest-connected
member the new host, the SDK follows (`sdk.on('host')`) and `net/sdk-channel.js` turns that into
`channel.onHostChange`. `client/game.js` then calls `handoffRole` (`net/handoff.js`):

- **The new host** builds a `HostSession` from its newest `host:snap` and the seat table. The world rewinds to that
  snapshot (a few ticks and one network trip older than the old host's last tick), the old host's player is removed,
  every other player keeps their slot, and acknowledged input seqs carry over, so nobody's inputs are applied twice.
  It loses only its own inputs since that snapshot (a few ticks of walking).
- **The seat table** is `host:seats` (`net/seats.js`), published next to the roster: member id, slot and name of every
  peer, and the host's slot. The wire format and `PROTOCOL_VERSION` did not change.
- **Every other peer** (`PredictedClient.hostChanged`) forgets the old host's timeline, says hello to the new host
  and keeps predicting. The hello is repeated every 0.5 s until the new host welcomes it; its slot is the one it
  had. A member the new host never heard of (its hello was never seen) gets a fresh slot and drops its stale inputs.
- **No snapshot ever heard** (the host left in the first moments): the new host starts the match over on the same
  world; peers join it again.
- A host the platform moves away from while its page is still alive steps down to a peer.

Tests: `test/handoff.test.js` runs it over the loopback hub (including 70 ms latency with 10–20 % loss) and over the
real Embedded App SDK (`ActivityData.changeHost`).

### Hidden tabs (the host's tab in the background)

Browsers stop `requestAnimationFrame` in a hidden tab and throttle its timers (to once a second, and about once a
minute after five minutes). The host's simulation is the match's clock, so a lagging hidden host would slow every
peer. What the game does (`client/game.js`, `client/pacer.js`; no Web Workers, the sandbox has `worker-src 'none'`):

- A watchdog timer runs the loop whenever no animation frame has run for 100 ms. Each call counts the *real*
  elapsed time and runs that many fixed 60 Hz ticks in one burst (up to 5 s, 300 ticks), then publishes **one**
  snapshot for the burst. A 1 Hz timer therefore still gives 60 ticks per second, in bursts.
- Every message a peer sends the hidden host also runs the loop. Messages are not throttled like timers, and each
  peer sends about 30 a second, so a hidden host with players in the match is driven at close to full rate.
- When the tab becomes visible a last burst runs before the first drawn frame.

**What the host's players see:** with peers in the match, nothing noticeable. With nobody else connected, nothing
to see. When the tab was throttled to once a minute (a long idle, nobody sending), the match catches up 5 s per
call and runs behind real time by the rest (`TickPacer.dropped` counts what was given up), and snapshots arrive in
bursts, so remote players look a little steppier (the interpolation delay hides one burst of 60 ticks only
partly). A hidden **peer** just keeps predicting; its next snapshot corrects it.

## GPU loss

`render/renderer.js` survives the GPU going away mid-match:

- **WebGPU `device.lost`** (a driver reset, the GPU process crashed): a new device on the same canvas; if that
  fails, WebGL2 on a fresh canvas element (a canvas that ever had a `webgpu` context cannot give a `webgl2` one, so
  the page swaps in a new element: `replaceCanvas` in `client/main.js`, `renderer.onCanvasChange`). A second loss
  within 30 s skips straight to WebGL2. The renderer's own `device.destroy()` is not a loss.
- **WebGL `webglcontextlost`**: the page waits 3 s for `webglcontextrestored` and rebuilds on the same canvas; if it
  never comes, WebGL2 on a fresh canvas.
- Rendering that throws on 3 frames in a row counts as a loss.
- Every mesh and texture ever uploaded is remembered and uploaded again in the same order, so the scene's handles
  stay valid. While recovering, nothing is drawn (the match carries on), and a notice says what happened. If every
  step fails the notice asks for a reload.

Tests: `test/gpu-loss.test.js` (the real backends against recording fakes) and `e2e/arena3d/touch.spec.ts` (a real
`WEBGL_lose_context` loss and restore in Chromium).

## Rendering

One forward pass: a directional light plus ambient, vertex colour × material tint × optional texture, a procedural
world-space floor grid, distance fog and a depth buffer. The low-poly look comes from per-face normals
(`render/meshes.js` `flat()`). WebGPU is used when `navigator.gpu` gives an adapter; otherwise the identical scene
draws through WebGL2 (Settings can force WebGL2). Each draw is `{ mesh, model, tint, grid?, texture? }`.

## Assets

- `BundledAssetSource` loads `assets/...` by relative URL. Fetching needs `connect-src 'self'`, so `sideroom.json`
  declares `"connect": ["self"]` (the sandbox default is `connect-src 'none'`). Images load through `<img>`
  (`img-src 'self'`).
- `.glb` is not an allowed bundle file type, so a model ships as one glTF `.json` with its buffers (and PNG/JPEG
  images) embedded as base64 `data:` URIs. `assets/gltf.js` reads meshes, the node hierarchy (matrix or TRS) and
  `baseColorFactor` / `baseColorTexture`. Skins, animation, morph targets, Draco and KTX2/Basis are out of scope
  (KTX2 needs a transcoder download).
- `ShelfAssetSource` reads a member's shelf through `byos_read` (D-389): the path is `<shelf id>/<object hash>`, SIDE
  ROOM asks the member once per object and hands back a URL that lives ten minutes (`sdk.commands.shelfObjectUrl`).
  The URL is on the shelf's storage host, so the fetch passes the sandbox CSP only when `connect` in `sideroom.json`
  names that host (see `docs/dev/design/byos-read-activities.md`). Guests never get it.

## Spatial voice hooks

`client/spatial-voice.js` exports `onListenerMove(pos, forward)` and `onSpeakerMove(memberId, pos)` (plus
`onSpeakerGone`). The game calls them every frame. Today they do nothing: `ingame_voice` is a reserved capability
(D-399), so the runtime refuses it. When the platform ships it, the implementation plugs in at `spatialVoiceFor()`
and the game code doesn't change. `sideroom.json` shows `ingame_voice` and `byos_write` in
`_reserved_capabilities_example`.

## Touch controls

On a phone or tablet (`(pointer: coarse)`, `?touch=1`, or on the first real touch of a laptop with a screen) the
game shows controls instead of asking for pointer lock (`client/touch.js`): a floating **move stick** under the left
thumb (8 directions like WASD, with a dead zone), **drag anywhere else to look**, a **Jump** button (held while
pressed) and a **Crouch** toggle (a thumb is busy looking, so it stays on until tapped again), and a **Menu** button
(there is no Esc). The stick and buttons become the same `BTN` bits as the keyboard and the drag becomes the same
accumulated integer yaw/pitch as the mouse (`InputState.addLook`, `setTouchButtons`), so the simulation, the wire
format and replay logs cannot tell a phone from a keyboard (`test/touch.test.js`). The layout is checked at 375x812
portrait and 812x375 landscape (`e2e/arena3d/touch.spec.ts`) and as a guest in the real sandbox
(`e2e/tests/arena3d-guest-touch.spec.ts`).

## Guests (`/play/<token>`)

A guest's bridge only has the data channel, `ready` and `storage`. `platform/sideroom-platform.js` never calls
`authorize`, `authenticate` or `getChannel`. It calls `getInstanceConnectedParticipants` and `setActivity` only
for members. The guest plays under the relay's `callsign`. `test/guest.test.js` runs a guest through the real SDK
with a bridge that records every command it is sent.

## Crash reports and replays

The host and each peer keep an input log in the replay script's format (`[tick, slot, buttons, yaw, pitch]`). The
page exposes `window.arena3d.tick()`, `.stateHash()`, `.inputLog()` and `.role()` for devtools and crash
reports. A log from tick 0 plus the seed replays through `replay/run.js` to the same hash
(`test/sim.test.js`).

## Make your own game from this starter

1. **Copy the folder** to `packages/starter-packs/activities/<your-game>/`. In `package.json` change `name` (and
   keep `jolt-physics` pinned). In `sideroom.json` change `id`, `name`, `description` and `max_participants`, and
   keep only the capabilities you use.
2. **Change the level** in `sim/level.js`: static blocks (`rotX` tilts a block about X, for ramps), the boxes,
   spawn points, the goal pad. Keep the numbers literal.
3. **Change the rules** in `sim/world.js`. `TUNING` holds speeds, gravity and push strength, `movePlayer()` does
   movement, and `afterStep()` holds game rules such as respawns and scoring. Stay inside the determinism rules
   above. New game state must go into `stateHash()`, `snapshot()` and `applySnapshot()`.
4. **Send what's new.** Extend `net/codec.js` (`encodeSnapshot`/`decode`, or a new message type) and bump
   `PROTOCOL_VERSION`. Add a codec round-trip test.
5. **Draw it** in `client/scene.js`. Add meshes in `render/meshes.js`, or load glTF through `assets/` (generate or
   export `.json` with embedded buffers). The HUD is `client/hud.js` and `client/index.html`.
6. **Record a new replay** if the rules changed: edit and run `node replay/make-script.mjs`, then commit
   `replay/script.js`.
7. **Prove it:** run `pnpm test` (the determinism gate must stay green), `npx tsc --noEmit -p tsconfig.json`, and
   `node tools/bundle.mjs` (the bundle must pass SIDE ROOM's rules). Then open `dist/replay/replay.html` in each
   browser and compare hashes.
8. **Ship it:** register the folder in `scripts/build-activities.mjs` (outside this folder) so the platform builds
   it with the other built-in activities.

## Known limits

- The renderer and the page have no Node-side pixel tests. They are covered by recording fakes, `replay.html`
  and playing the demo. A Playwright spec for `replay.html` in all three engines is a follow-up outside this
  folder.
- Touch has no pause, no gamepad and no haptics; the stick reads 8 directions (the simulation takes a button set,
  not an analogue vector).
- The local player is drawn at its latest predicted tick, with no render interpolation between ticks. At
  refresh rates far above 60 Hz the camera steps slightly.
- Host migration works over the platform's `HOST_CHANGED`; the local stand-ins (`bc-channel.js`, the fake platform)
  never move the host, so closing the first tab ends local play for the others (`test/handoff.test.js` is the proof).
- A WebGPU loss that leaves neither WebGPU nor WebGL2 is a reload; there is no software renderer.
