- [x] **VOX-SFU-008** [BE] Egress governor (budget, per-tier priority downgrade, notices) *(sr-voice governor.rs: budget voice.egress_budget_mbps (0 = off), severity steps up every 5 s over budget and down every 15 s under 80 %, Level 0 capped first and Patrons last, QUALITY notice (op 13), sr_voice_governor_severity gauge)*
- [x] **VOX-SFU-009** [BE] Metrics (rooms, participants, egress/ingress Mbps, loss, CPU) *(rooms, participants, egress/ingress bps, loss ratio, forwarded packets; no CPU gauge yet)*
- [x] **VOX-SFU-010** [BE] Graceful drain on shutdown (RECONNECT hint) *(drain() closes clients with 4015 and refuses joins)*
- [x] **VOX-SFU-011** [TEST] Load test harness (headless senders/receivers in Rust) → 300 Mbps target *(sr-voice loadtest.rs and examples/loadtest.rs: headless str0m senders and viewers against SfuCore, times only the core. P13: the SFU is now sharded (`SfuConfig::shards` / `voice.shards`, default auto = half the cores, max 8): rooms are spread over several media actors by channel id, each with its own UDP sockets, id space and 1/N of the egress budget; ICE-TCP, RESUME, the node-wide participant cap, cross-shard rejoin and metrics are handled in server.rs (tests e2e.rs: rooms_on_different_shards..., joining_a_channel_on_another_shard..., resume_finds_its_shard..., ice_tcp_reaches_the_shard...). `--shards N` runs N cores at once. Release runs on the shared Windows dev box (32 logical cores, other agents running): one actor 312 Mbit/s = 58 % of a core (an earlier run on a quieter machine said 110 %); 4 concurrent shards of that load = 1248 Mbit/s with each shard at 78 % of its core (contended); 4 shards carrying 319 Mbit/s in total (3 publishers + 17 viewers each) = 8.5 % per shard core, 0.34 cores in all, so the 300 Mbit/s at under 50 % CPU target is met. The AX42 run (P10-VBE-1 asked for real-hardware numbers) is still to do)*
