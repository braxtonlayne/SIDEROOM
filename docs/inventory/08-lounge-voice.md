The AX42 run (P10-VBE-1 asked for real-hardware numbers) is still to do)*

## VOX-E2E — End-to-end encryption
- [x] **VOX-E2E-001** [BE][WASM] `sr-e2ee`: OpenMLS group per call, key packages, add/remove proposals, commits, welcome processing _(P14: crates/sr-e2ee/src/mls.rs on openmls 0.9.1, ciphersuite MLS_128_DHKEMP256_AES128GCM_SHA256_P256 (D-249): one group per call (the gateway hands out a random group id and picks the one creator), per-session P-256 signature keys certified by the identity key inside the basic credential, key packages, commits with adds and removals checked against the voice-channel roster (one leaf per user, reconnects replace the old leaf), welcomes with the ratchet tree, external Remove proposals, epoch tracking and the per-sender exporter secret `MLS-Exporter("SideRoom Secure Frames v1", user id u64 LE, 16)`. - [x] **VOX-E2E-002** [WASM] Frame encryptor/decryptor (AES-128-GCM, frame counter nonce, 8-byte tag, codec-aware unencrypted header ranges for Opus/VP8/H.264) _(P14: crates/sr-e2ee frame.rs and codec.rs: AES-128-GCM via RustCrypto, nonce = 8 zero bytes + u32 counter, tag truncated to 8 bytes and checked in constant time, a 4-byte encryptor instance id in the trailer so a restarted worker never repeats a nonce; clear bytes: none for Opus, 3/10 for VP8 delta/key frames, start codes + NAL headers + SPS/PPS/AUD + slice header through pps_id for H.264, with start-code emulation avoided by re-encrypting; the same code in WASM as crates/sr-e2ee-wasm (`loadE2ee`); tests in the crate, tests/vectors.rs and packages/wasm/test/e2ee.test.ts)_
