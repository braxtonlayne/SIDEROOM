## 6. Messages

### 6.1 Display
- Cozy (default) and Compact modes. Grouping of consecutive messages (≤ 7 min, same author). Timestamps (hover full date). "NEW" divider. Date dividers. Jump-to-present bar. Unread banner "N new messages since…" with Mark as Read.
- Author: avatar (click → profile popout), display name in highest-role color (gradient roles supported), role icon, server-tag chip, APP/BOT badge, timestamp, "(edited)."
- Content: markdown via `sr-markdown`: bold, italic, underline, strike, spoiler `||`, inline code, code blocks with syntax highlighting (highlight via a Rust `syntect`/`tree-sitter` → WASM, or Shiki), block quotes, headers `#`/`##`/`###`, subtext `-#`, lists, masked links `[text](url)`, timestamps `<t:unix:R>`, mentions (`@user`, `@role`, `#channel`, `@everyone`/`@here`), custom emoji `<:name:id>`, slash-command mentions `</cmd:id>`, guild navigation `<id:customize>`, and **SIDE ROOM mentions** `<cinema:title_id>` / `<library:series_id>`, which render as rich cards.
- Attachments: image/video grid (1–10 media), mosaic layout, lightbox (zoom, download, open original), alt text, spoiler blur, generic file card (icon, name, size, download), audio player, **voice message** (waveform, speed), **expired large file** chip (D-043).
- Large attachments (LNG-CMP-007, D-271): a file over 64 MB gets a multipart slot; the composer sends the parts three at a time, retries a part, and after a stall asks `GET /channels/{id}/attachments/{upload_id}/parts` which parts arrived and sends only the rest. For multipart slots (never single-PUT uploads) the browser keeps the file in its IndexedDB ledger (`sideroom-uploads`, store `chat`): after a reload the file reappears in that channel's composer tray and continues uploading; the message is still sent by the user. At most 5 rows per browser profile (the oldest is dropped and its slot aborted with `DELETE .../attachments/{upload_id}`); a row is removed on complete, on cancel, when the server answers 404 for the slot, and when it is older than 20 h (the server sweeps at 24 h); when IndexedDB cannot store the row (quota, blocked) the old localStorage record (name, size, lastModified) is the fallback and the user picks the file again; no `navigator.storage.persist()` prompt; sign-out aborts the open slots and clears both stores. "Support SIDE ROOM" in the header menu stays on `/support` (D-270).
- Embeds: link unfurls (OpenGraph/oEmbed fetched server-side by `sr-unfurl` with an SSRF-safe resolver, run by the `messages.unfurl` job after the message is sent; the client loads only the proxied image URL, D-176), rich embeds from bots, **YouTube/Twitch/Spotify-style playable embeds** (privacy-enhanced iframes, click to load), and Cinema/Library cards ("Watch together" button).
- Stickers, polls (question, up to 10 answers with emoji, duration, multi-select, live results, end early), components (buttons, select menus) from apps, reactions (emoji + count, super reactions as free burst reactions, tooltip of who reacted, add-reaction picker), reply preview line, forwarded message frame, thread starter ("N messages ›"), system messages (joins, boosts → "contributed to Server Support," pins, thread created, call started/ended, channel follows).
- **A message's text outside the message itself is plain text, and a blocked or ignored author's is not shown (D-729, D-730; SEC-AUD-246..248).** The reply line above a reply, the Inbox's mention list, the direct-message toast and the delete confirmation show the text by D-716's rule (a spoiler's text is never shown and "[spoiler]" stands in, a mention reads as a name, a custom emoji as `:name:`, a link as its label, one line, cut at 140 characters; empty until the parser is ready, never the raw text; a message that is only an attachment keeps each place's own words: "Click to see attachment", the attachment count). For a blocked or ignored author (the lists the message list uses, read live) the reply line, a pin in the pins panel, a search hit with the lines either side of it, and the card of a message link show the Lounge's "blocked message" wording ("1 blocked message", "1 ignored message") in place of the text and attachments, and no name: the reply line stays a button that jumps to the message; the pins panel gives a pin its "Show message" (this pin only); the Inbox does not list the mention at all (the server stops sending it, D-721; the web drops it as well); search results and the link card have no reveal. **The pins panel and the search lines (D-739, D-737; SEC-AUD-262, SEC-AUD-264).** A pin is a whole message, so the pins panel draws it with the message list's renderer (markdown as in the list: a spoiler hidden until it is clicked, mentions as names, bold as bold, a list or a code block as a block; no embeds, stickers or reactions; the panel scrolls); the "Attachment" and "No text" lines stay for a pin without text, and until the parser is ready the panel draws no text rather than the typed text. A search hit shows the server's snippet, which is plain text already (cut from the index, where a spoiler is `[spoiler]`); where the web has no snippet, and for the lines either side of a hit, it writes the message by D-716's rule, never as typed. The one-line text (Message Requests, the thread row, the reply line) writes a timestamp in the viewer's zone in its own style, except the relative style (`<t:...:R>`), which it writes as the short date and time (`f`): a one-line text is not redrawn as time passes, so "in 5 minutes" would go stale. The typing line does not name an ignored account (the web filters it, and the store keeps the entry); the gateway sends no `TYPING_START` across a block in either direction, as it sends no presence (D-744), and the web's filter of a blocked account stays for an older server.

### 6.2 Message actions
Hover toolbar: add reaction, quick reactions (frequently used), reply, forward, create thread, edit (own), ⋯. Context menu: Add Reaction ▸, Edit, Reply, Forward, Create Thread, Copy Text, Apps ▸, Mark Unread, Copy Message Link, Pin/Unpin, Speak Message, Remind Me (feature module), Bookmark (feature module), Delete (own, or with Manage Messages), Report (opens the report dialog, `apps/web/src/moderation/reports`), Copy Message ID (Developer Mode). Shift-click shortcuts (delete without confirmation, etc.). Up-arrow edits the last message.

### 6.3 Deletion semantics (D-121/D-122)
Delete → `visibility = user_deleted` → `MESSAGE_DELETE` dispatched (all clients remove it) → purge after 30 days (the hourly `messages.purge_deleted` job, `crates/sr-server/src/jobs.rs`; a message under a moderation hold is never purged). Bulk delete (moderators) behaves the same. No user-visible "deleted message" stubs (Discord parity). The posting gate (D-423) also covers edits with new content or attachments, crosspost and poll votes; a restricted member can still delete their own messages (D-566).

### 6.4 Composer
Multi-line rich input (Slate- or Lexical-based) with inline emoji/mention rendering · `+` menu (Upload a File, Create Thread, Create Poll, Use Apps, Share a Cinema/Library title) · paste-to-upload · drag-and-drop overlay ("Upload to #channel") · upload queue with per-file edit (rename, spoiler, alt text, remove) · size check against `effective_limits` before upload, with a friendly "Max 30 MB. Patrons can send up to 500 MB" hint · gift slot **removed** · GIF picker (operator-configured provider: Tenor/Klipy/self-hosted, or disabled) · sticker picker · emoji picker (search, categories, server sections, skin tone, frequently used, favorites) · apps/slash-command button · voice message record button (mobile and desktop) · autocomplete popups for `@`, `#`, `:`, `/` · typing indicator ("X is typing…", "Several people are typing…") · slowmode countdown · reply bar · edit mode (Esc to cancel, Enter to save) · character counter near the limit · "You do not have permission to send messages in this channel" state · markdown preview of spoilers.

## 8. Threads & forums
Discord parity: threads panel (active/archived, joined), thread view in a side pane or full width, auto-archive durations, private threads (invite-only), thread member list, the row under a message (the thread's name and message count, which follows live: the web counts a message written in or deleted from a thread it holds, the way the server does (a message a moderator restores counts at once, whatever its id, D-723), and shows "50+ messages" once the count reaches the server's cap of 50, D-718; the same wording in the Threads list and on a forum post's row, and a second line with the avatar and name of whoever wrote the latest message, its text on one line (cut by the same rule, D-728, D-735: a run of markup the cut falls inside is closed at the cut) and its time as a relative one ("just now" under a minute, "5m ago", "3h ago", "2d ago" up to 30 days, then "more than 30 days ago"; the full date and time in the tooltip; the row refreshes once a minute while it is on screen, with one shared timer for all rows, paused in a hidden tab; the message list keeps its own time format, D-700); a blocked or ignored author's text is replaced by the "blocked message" wording; one line when the thread has no message yet; D-689, LNG-THR-006). The "started a thread" notice row carries the same chip under its sentence, so a thread started without a message shows its activity there; the row is live too: when it arrives while the channel is open, the web gives it the chip at once from the thread it already holds (name and count, no latest message until someone writes; no request, D-715), and a live reply then moves it; when the thread was started from a message the chip sits under that message only (D-701), "N new posts" for forums, forum post creation modal (title, content, tags, media), and forum layouts.

## 9. Search
Search bar in the header ("Search <server>" / "Search <username>"). **On a phone (D-740; SEC-AUD-263)** the inline box is hidden and the header shows a search button instead; it opens the same search (box, filters, results) as a sheet that fills the chat pane (the pane switching by swipe works again once it closes), with the box focused. The sheet closes with its back button, Escape or the back gesture, and by choosing a hit, which jumps to the message; focus returns to the button. Filters `from:`, `mentions:`, `has:` (link, embed, file, image, video, sound, sticker, poll), `before:`, `during:`, `after:`, `in:`, `pinned:`, `authorType:`. Results pane with jump-to, sorted by newest/oldest/relevance. Backed by Tantivy, permission-filtered at query time, and excludes deleted messages. The indexed text is the message as plain text (spoilers as `[spoiler]`, a mention as `@user`, `@role` or `#channel`, a timestamp as a UTC date), with a list, quote, heading or code block on its own line so that `two` and `- a` are two words (D-722, D-731); messages indexed before that keep their old text until `sr-cli reindex`.

## 10. Notifications
Per server, category, and channel: All / Only @mentions / Nothing. Precedence, most specific first: channel, category, the member's per-server choice, the member's global default (`/users/@me/notification-defaults`), then the server's `default_message_notifications`; this applies to servers only, DMs keep their own scope (D-165). **One order and one set of mutes for push and the open app (D-727):** a channel, its category (for a thread, its parent channel, as the push engine passes it) or the whole server being muted silences a message; the open app reads the server's default from the server object and the person's own default from `/users/@me/notification-defaults` once when the Lounge boots and again on `SR_NOTIFICATION_DEFAULTS_UPDATE` (Settings > Notifications updates it at once; until it has been read the desktop decision runs without it), so the open app follows the whole order (D-732). **What a mention is (D-725, D-726):** a message that names the viewer, replies to them with the ping on, pings `@everyone`/`@here` (unless suppressed) or pings a role they hold (unless suppressed); the two Suppress switches also keep the mention badge off, and a role mention raises the desktop notification and the mention sound like any other. A reply pings the replied-to author unless the sender turns the ping off in the composer; the push says "replied to you" only for a reply that pinged. Also: Suppress @everyone/@here, Suppress role mentions, Suppress highlights, Mute (15 min … until I turn it off), Mobile push toggles. Inbox (top-right): Mentions, Unreads, For You tabs. Web Push through VAPID (PWA). Badges and desktop notifications with sound packs (themes may supply sounds). **A notification shows a message as plain text (D-716)**, in the open app and in the push the server sends: a spoiler's text is never shown (the word for it stands in: "[spoiler]"), a mention reads as a name (`@name`, `#channel`, `@role`), a custom emoji as `:name:`, a link as its label, line breaks as spaces (a list, quote, heading or code block stands apart from the text around it, D-722), a timestamp as a date and time (D-731), cut at 140 characters; when the parser is not ready the body is empty, never the raw text. **Nothing from an account the viewer blocked or ignores (D-717):** the open app raises no notification and plays no sound for their messages (a mention or a direct message) or reactions; their mention gives no mention badge, live or after a reload (D-721: the server's rule since SEC-AUD-011, which the open app now follows), and it is not in the Inbox's Mentions tab; the channel is still unread and the message list shows its "blocked message" row; the push rule is unchanged. An account that blocked the viewer still counts live until a reload (the client is never told who blocked it). **Reaction notifications (D-703):** when someone reacts to the viewer's own message, the open app raises a desktop notification ("{name} reacted {emoji} to your message") under the rules of a message notification (permission granted, not while that channel is focused, not in Do Not Disturb or Streamer Mode, not for a muted channel or server, not from a blocked or ignored account (D-717), never for the viewer's own reaction), with no sound, no unread mark and no push to a closed app; the notification's second line is the text of the message that was reacted to (D-712): the loaded message, else the last 20 read this session, else one `GET /channels/{id}/messages/{id}` raced against 2 seconds (empty when it is late, cannot be read, or the text cannot be made plain; messages are plain text on the server, no conversation hides them from it), never fetched when the decision is no, when notifications are off, or for the viewer's own reaction, and never put into the message list; Settings > Notifications has the switch (on by default). The email digest switch was withdrawn until a digest exists (D-704); the stored preference is kept and ignored. **Phone glyph (D-702, D-711):** a member who is online on a phone and nowhere else shows a smartphone glyph (the `smartphone` icon of `packages/ui`; the handset `phone` icon stays for calls) in place of the green dot (member list, profile, friends, DM list and header, the viewer's own avatar), named "Online on a phone"; idle, Do Not Disturb and offline keep their dots, and no setting hides it.

## 13. Built-in "no-bot-needed" features (feature modules, doc 11 §1.2)

## 14. Limits (Discord parity defaults, operator-configurable)

| Limit | Default |
|---|---|
| Message length | 2,000, fixed (D-662; the composer and the markdown engine know the number; a setting for it is later) |
| Attachments per message | 10 |
| File size | 30 MB by default: the operator's `uploads.standard_limit_bytes` (1 MiB to 500 MiB, applies to the next upload; Patron 500 MB; server levels per doc 08). Above it a file is "large" and expires after `retention.large_file_days` (default 7, 1 to 365; D-662) |
| Servers per user | 200 by default, **enforced**: the operator's `guilds.max_per_user` (Admin > Settings, 1 to 1,000; D-659). Created and joined servers count together, the Staff Server does not; bots are not limited |
| Channels per server | 500 |
| Roles per server | 250 |
| Emoji per server | 250 static + 250 animated |
| Stickers / soundboard sounds | 60 / 48 |
| Members per server | 25,000 by default, **enforced**: the operator's `guilds.max_members` (Admin > Settings, 2 to 1,000,000; D-660). Counts every membership of the server, pending members and bots included; the Staff Server has no limit |
| Pins per channel | 250 |
| Friends | 1,000 |
| Group DM size | 10 |
| Embeds per message | 10 |
| Reactions distinct per message | 20 |

The defaults live in `crates/sr-chat/src/limits.rs` (messages, attachments, channels, roles, pins, reactions, embeds), `social/mod.rs` (friends 1,000, group DM 10 members) and `settings/expressions.rs` (emoji, stickers, soundboard); the 4,000-character message ceiling is `EXTENDED_MAX_CHARS` in `sr-markdown`. The two server limits are checks, not targets (wave 66, D-659 to D-661): creating a server (plain or from a template) and joining one (invite, vanity code, Server Directory, an approved membership application, adding a bot) are refused at the limit with `400` and Discord's codes, `30001` "Maximum number of guilds reached (N)" (N is the number in force) and `30019` "Maximum number of server members reached"; an application stays pending and an invite use is not consumed. The count and the insert are one transaction under a per-account (or per-server) lock, so parallel requests cannot pass a limit (`crates/sr-db/src/guild_caps.rs`). Nobody is exempt, staff and the Owner included; only the Staff Server is (never counted, never full, so appointments never fail on a limit). Lowering a setting removes nobody: an account over the limit keeps its servers and cannot create or join another until it is under, and a server over the limit keeps its members and admits nobody until it is under. A change applies to the next request, an unreadable stored value reads as the default, and the guild object carries `max_members`. The client answers each refusal with its own sentence (`lounge.limits.*`).

## 16. Added after Phase 1
- **Channel permissions.** Editing and deleting a channel evaluate `MANAGE_CHANNELS` with the channel's overwrites (D-570); the client evaluates the same rules in `apps/web/src/lounge/permEngine.ts`.
- **Listening rooms and the jukebox.** A voice channel's jukebox can publish a listening room (`apps/web/src/lounge/rooms/`); the `jukebox.rooms` job moves a room between `cursor` and `stream` mode (D-512). See [lounge-voice-video.md](lounge-voice-video.md).
- **Discord bridge.** Off on every server; only the server owner switches it on (D-381). Two modes, "Only bridge these" and "Bridge the whole server", where SIDE ROOM is the master copy of permissions (D-386). Routes: `crates/sr-api/src/routes/guilds/bridge*.rs`; engine: `crates/sr-bridge`; client: `apps/web/src/lounge/bridge/`. One Discord channel maps into at most one SIDE ROOM server per instance (D-609).
- **Gateway resync.** When a gateway pump misses events, the server rebuilds its state and re-sends it on the same socket: a fresh READY and GUILD_CREATEs for a user topic, a per-member GUILD_CREATE and an `SR_RESYNC` marker for a server topic, the marker alone for the platform topic. Sessions keep their id, so calls continue; nothing is shown to the member; bot sessions are not resynced (D-646). On `SR_RESYNC` for a server the client marks that server's message windows stale and clears typing indicators for its channels (`apps/web/src/store/reducer.ts:502`).
- **Account restrictions.** The posting gate (D-423, D-566) answers `403 900124 SR_ACCOUNT_RESTRICTED` on posting routes while a restriction is on the account.
