## Extensions

Lands on `feat/p16-ext` (LNG-SSET-050, EXT-PKG-006: the server-wide theme, the accent colour and packs added to a server).

- [ ] **L-40 (P16-EXT-1, D-280) The server look precedence is documented and asserted.** `docs/10-design-system-and-theming.md` section 2 (the "Users can pick one theme" paragraph): the full order from the built-in theme to the Theme Store preview, the one switch "Allow server themes" covering theme and accent together, and "the manager's accent wins over the theme's accent token". `docs/specs/developer-platform.md` client paragraph: the same in one sentence next to `useAppliedTheme`. `apps/web/src/packages/serverAppearance.ts` doc comment names D-280. Tests: the `packages/serverAppearance` vitest gains "accent over the theme's accent token" and "nothing when the switch is off" if not already there, and the `LoungeShell` or `ThemeProvider` test asserts a Theme Store preview is laid over the server theme. Size: XS.
- [ ] **L-41 (P16-EXT-2, D-281) A guild theme is stored as `lounge`.** `crates/sr-api/src/routes/packages/handlers.rs` (`enable_for_guild`): for a theme, `all` is accepted and written as `lounge`; the OpenAPI description of the body's `section` says "`all` means the Lounge for a server; a server theme never recolours Cinema, Library or the Entrance (D-281)". `docs/10-design-system-and-theming.md` section 2: "recolor that server's channel list and header" becomes "recolour the Lounge while that server is open (channel list, header, chat, members, voice and party rooms), never Cinema, Library or the Entrance". `docs/specs/developer-platform.md` "Not built" sentence: drop "a theme enabled for a whole server" and "adding the files of an emoji, sticker or sound pack to a server" (both built on this branch) and add the two routes to the "Routes" line (`POST .../{package}/import`, `GET|PATCH /guilds/{id}/appearance`). Tests: the `sr-packages` Postgres test asserts the stored section; the `Extensions.tsx` test is unchanged. Size: XS.
- [ ] **L-42 (P16-EXT-3, D-282) Packs need `MANAGE_GUILD_EXPRESSIONS` alone.** `crates/sr-api/src/routes/packages/handlers.rs`: a `require_manage_or_expressions(settings, user, guild, gate)` next to `require_manage` that accepts `MANAGE_GUILD` or `MANAGE_GUILD_EXPRESSIONS` (MFA gate as today, D-223); `appearance.rs::import_pack` uses it; `disable_for_guild` uses it when the enablement's kind is a pack and keeps `require_manage` for themes, recipes and templates (look the kind up before the permission check, 404 as today when nothing is on). Doc comments, the route matrix rows and the OpenAPI descriptions say the rule; regenerate OpenAPI and the api-client. Web `apps/web/src/settings/server/ServerSettings.tsx`: the Extensions section is visible for `MANAGE_GUILD` or `MANAGE_GUILD_EXPRESSIONS`; `sections/Extensions.tsx` offers the kind select over emoji, sticker and sound packs only, hides the Server look card and the Turned-on list's non-pack rows, and hides recipe, theme and template kinds when the viewer lacks `MANAGE_GUILD`; the "Remove from server" button and its aria-label name the count of items the pack added (from the enablement, add `item_count` to `Enablement` for packs, or count `guild_pack_items` in `enabled`). `docs/07-permissions-and-staff.md` expression paragraph and `docs/specs/developer-platform.md` "Servers (`MANAGE_GUILD`)" routes line: "packs: `MANAGE_GUILD_EXPRESSIONS` suffices (D-282)". Tests: `sr-api` route tests (expressions-only member may import and remove a pack, may not enable a theme or apply a recipe; `MANAGE_GUILD` without expressions may still import, as today), `route_matrix`, web `extensions` vitest (kinds shown per permission, count on the button). Size: S.
- [ ] **L-43 (P16-EXT-4, D-283) Sticker packs refuse WebP at upload; WebP dimensions are checked.** `crates/sr-packages/src/validate.rs` pack branch: for `StickerPack`, a WebP file is an error "`{file}`: stickers are PNG, APNG or GIF files" (emoji packs keep WebP); `image_dims` (or a sibling) reads the WebP canvas size from the `VP8 `, `VP8L` and `VP8X` chunks so the pixel cap applies to WebP emoji too. `docs/specs/developer-platform.md` kinds-and-manifests line: "stickers PNG, APNG or GIF; emoji also WebP". `sr-cli package validate` prints the new line like any other error. `crates/sr-api/src/routes/packages/appearance.rs`: the sticker skip message stays as the guard for packs approved before the change; its doc comment names D-283. Tests: `sr-packages` validator unit tests (WebP sticker refused, WebP emoji accepted, oversized WebP emoji refused by dimensions). Size: XS.
