# Entrance isolation: a visitor without a login gets only the code their page needs

Written 2026-10-29 by the owner's delegate on `docs/p30-entrance` (based on `integration/phase30`). Design for D-385 and for wave 30b of [roadmap-p27.md](roadmap-p27.md) (items `SEC-ENT-*`). It is a design, not a report: the numbers under section 6 were measured on the wave-29 build (`p29-integ/apps/web/dist`); everything else is what the wave builds.

**The owner's rule (2026-10-29, verbatim, binding).** "No real code should ever be served to the landing page or login page, only what is needed. I'd want the landing page's code to tell visitors nothing about what's inside. So none of the stuff or anything should ever be served before a user is logged in." And, the same day, as the general rule: **"if an individual without a login can see it, only the code that is absolutely necessary should be loaded into their browser."** The owner also decided that the help pages (the handbook, its legal pages and What's new) go behind login.

The occasion was the Cinema mini player rendering on the landing page. The cause is structural: `apps/web/src/main.tsx` is the one entry of the one `index.html`, and it imports the whole router (every route path with its lazy chunk), `VoiceBridge`, `IncomingCallOverlay`, `MiniPlayerMount`, `ReportDialog`, `ReportsFlagSync`, `PwaHost` and the service worker. A visitor who opens `/` downloads 798 KB (253 KB gzip) of JavaScript that names every area of the app, and may then fetch any other chunk by name. D-384 kept crawlers out; this keeps the code out.

## 1. The design in ten lines

1. **Every public surface is its own minimal bundle or plain HTML.** The public build has one HTML entry per surface: `landing` (`/`, `/join/$code`), `auth` (login, 2FA, login link, register with its age and rules consent, forgot, reset, verify-email, email-change cancel, the Discord callback), `invite` (`/invite/$code`, `/template/$code`, `/no-invitation`), `profile` (`/~handle`, wave 34). The legal pages (`/house-notes`, its terms, privacy, rules and credits anchors) and the error pages are plain HTML with no script at all. Nothing public is built from a module under an app directory.
2. **The app is one gated build.** `dist/app.html` and `dist/app/*` are served by `sr-server` from `[web] root` only to a request with a valid `sr_session`. Caddy serves the public files and proxies `/app`, `/app/*` and every path that is not a public surface to `sr-server`.
3. **No oracle.** Without a session, a navigation to any path that is not a public surface is `302 /login?next=<path>` whether it exists or not; a fetch under `/app/` is `401` with an empty body whether the file exists or not; the API's unknown path answers `401` to anonymous callers. The session is checked before the file system.
4. **Private caching.** App files: `Cache-Control: private, max-age=31536000, immutable`; the app shell: `private, no-store`; `Vary: Cookie` on both. Nothing of the app is ever `public`.
5. **Two policies.** The public shells get a plain CSP (no `wasm-unsafe-eval`, `blob:`, `frame-src`, no voice or activity origins); the app shell keeps today's. Both come from `csp.ts`; the app policy reaches `sr-server` as `dist/app/csp.txt`.
6. **Login is a full navigation.** Sign-in ends in `location.assign('/app')` or a validated `next`. `/app` is the neutral door; the app's router sends the member to their last section. No public bundle knows a section's path.
7. **Logout purges.** `POST /sr/auth/logout` and `logout-all` answer with `Clear-Site-Data: "cache", "storage"`; the app first asks the service worker to delete the app caches. A session revoked elsewhere is purged at the next `302`/`401`.
8. **The service worker precaches public files only** (`sr-static-<build>`); app files go to `sr-app-<build>` cache-first on use, never precached, deleted on logout, on a `401` and on a new build. The worker names no app path.
9. **Two manifests.** `/manifest.webmanifest` (public): `start_url: /app`, no shortcuts. `/app/manifest.webmanifest` (gated, linked by `app.html`): the shortcuts. Same `id`. The install prompt stays on signed-in pages.
10. **Three proofs on every wave, per surface.** `scripts/check-entrance-isolation.mjs` fails the Web job when any public surface's closure holds an app identifier, exceeds its budget or loads a module outside that surface's allowed list; `e2e/tests/entrance-isolation.spec.ts` fails when an anonymous session's network log on any public surface has an app file or a `200` for an app path; `crates/sr-server/tests/web_gate.rs` fails when an app file is served without a session or without private caching. Prod-smoke runs the first two through the installed Caddy.

## 2. The public surfaces and their bundles

**Why per surface, and why two builds.** One Vite build with many HTML entries lets Rollup share chunks among the entries; between public surfaces that is fine (all public), but between a public surface and the app it would put the public/private line inside Rollup's chunking choices, where a shared chunk that pulls an app module in would leak silently until a check caught the symptom. So: **two builds** (`vite.public.config.ts` → `dist/` public files under `/entrance/`; `vite.config.ts` → `dist/app.html` and `/app/*`), merged by `scripts/build-web.mjs`. The line between public and private is a directory. Inside the public build, **one HTML entry per surface**, so each surface's first load is its own closure, measured and checked on its own; chunks shared between two public surfaces (React, the router, `@sideroom/ui`, `api/client`) are allowed because every surface may load them.

| Surface | Shell | Paths | May import (`apps/web/src/public/<surface>/ALLOWED.ts`, enforced by a `resolveId` guard in the public config and by a Vitest) | Budget (gzip, first load) |
|---|---|---|---|---|
| landing | `dist/index.html` | `/`, `/join/$code` | `routes/entrance/{Landing,entranceCopy}`, `components/{Door,EntranceShell,icons}`, `api/{client,entrance}`, `lib/{inviteCode,compliancePublic,useNoindex,enterApp}`, `i18n` core (`entrance`, `a11y`, `pwa`), `a11y/announcer`, `pwa/register`, `@sideroom/ui` | 120 KB |
| auth | `dist/auth.html` | `/login`, `/login/2fa`, `/login/link`, `/register`, `/forgot`, `/reset/$token`, `/verify-email/$token`, `/email-change/cancel`, `/oauth/discord/callback` | landing's list plus `routes/entrance/{Login,TwoFactor,LoginLink,Register,PasswordReset,VerifyEmail,EmailChangeCancel,DiscordCallback,BanAppeal}`, `components/{AuthSplit,FormParts,PasskeyButton,VerifyEmailBanner}`, `api/passkeys`, `lib/{validation,mfaMethods}` | 150 KB |

Each surface has its own entry file (`src/public/<surface>/main.tsx`) that mounts a router with that surface's routes only and that surface's not-found page (the entrance's "nothing here", never a redirect to an app route). The `enterApp` helper (section 4) is the one thing every surface shares that knows an app URL, and the only one it knows is `/app`. The registration consent step (the age declaration of D-294 and the rules acknowledgement, which links `/house-notes`) is part of the `auth` surface. The OAuth2 consent screen `/oauth2/authorize` is shown to signed-in members only (an anonymous arrival gets `302 /login?next=/oauth2/authorize?...`), so it stays in the app build; if the owner meant a different consent screen, it is a surface like the others.

**The app build.** Today's `main.tsx` becomes `src/app/main.tsx`; its router loses the public routes except `/` and `/app` (both redirect to `lastSection`). The lazy chunks keep their names; they are no longer public. Everything mounted above the router today (`VoiceBridge`, `IncomingCallOverlay`, `MiniPlayerMount`, `ReportDialog`, `ReportsFlagSync`, `ReauthHost`, `PwaHost`, and wave 30's `PlayerHost`) stays where it is: it is in the app build and therefore behind the gate. `/help`, `/help/whats-new` and the handbook's legal pages are app routes.

**Catalogs.** The public build registers `messages/<locale>/{entrance,a11y,pwa}.ts` only; the app registers those and `en.rest`. `CatalogGate` and `corePaths.ts` stay in the app for its own first paint. `corePaths.test.ts` gains the public surfaces' module lists as input. The legal page's strings (`entrance.houseNotes.*`) are rendered at build time into static HTML per locale (section 7), so they leave the runtime catalog of the public bundles.

**Styles.** `tokens.css`, `fonts.css`, `a11y.css` in every entry; the app's section stylesheets are unreachable from a public surface. `check-css-tokens.mjs` is unchanged. `__SR_VERSION__` is defined for the app build only. The public build defines `import.meta.env.SR_BUILD = 'public'` so a shared component can drop an app-only branch at build time.

## 3. Server-side gating

**Considered: Caddy `forward_auth`.** Caddy would call `sr-server` (`GET /internal/session-check`, loopback) for every gated request and serve the file on `2xx`. It keeps file serving in Caddy and adds no serving code in Rust. Against it: the gate would live in a Caddyfile that self-hosters edit and that the systemd route and any other proxy must reproduce by hand; the `302` versus `401` choice, the `next` validation, `Vary` and the cache headers and the no-oracle rule would be Caddy directives pinned only by a smoke test against an installed Caddy; one round-trip per asset (about 230 files on a cold app start); and a deployment without Caddy would have no gate at all. The design wants one gate in one language with a Rust test on every PR.

**Chosen: `sr-server` serves the app behind the session check.** A new module `crates/sr-server/src/web.rs` and `[web]` in `sr-core::config`:

```toml
[web]
# The built apps/web/dist. Unset: sr-server serves no documents (the API only, as today).
root = "/srv/web"
# Serve the public surfaces too (single-binary deployments without a proxy; CI). Default false: Caddy does.
serve_public = false
```

Routes outside `/api`:

| Request | No valid session | Valid session |
|---|---|---|
| `GET /app`, `GET /app/`, and any navigation (`Sec-Fetch-Mode: navigate`, or `Accept` preferring `text/html`) to a path that is not a public surface or file | `302 Location: /login?next=<path+query>` when `<path>` is a safe same-origin path (one leading `/`, no `//`, no scheme, under 2 KB), else `302 /login`; `Cache-Control: no-store`; no body | `200` `app.html`; `Cache-Control: private, no-store`; `Vary: Cookie`; the app CSP; `X-Robots-Tag: noindex, nofollow` |
| `GET /app/*` (hashed assets, `/app/manifest.webmanifest`, `/app/THIRD_PARTY_NOTICES.md`) | `401`, empty body, `Cache-Control: no-store`, no `WWW-Authenticate`; identical for a file that does not exist | `200` the file; hashed names `private, max-age=31536000, immutable`; the manifest and notices `private, no-cache`; `Vary: Cookie`; a missing file `404` (reachable only with a session) |
| `HEAD` | as `GET` | as `GET` |
| other methods | `405` | `405` |

The check is `sr_api::auth`'s session extractor with the API's policy (expiry, revocation, trusted devices) and runs before any path is resolved. Bot and bearer principals are not sessions and get the anonymous answers. The gate has its own per-IP bucket for `401`s, separate from the API's limiter.

With `serve_public = true` the module also serves the public files with today's Caddy headers (`public, max-age=31536000, immutable` under `/entrance/*` and `/fonts/*`; `no-cache` for the shells, `sw.js`, the manifest, the offline page), the public CSP, the surface table of section 2 (path → shell), the legal pages (section 7) and the error pages. CI and a single-binary install use this; the Caddyfile is a faster front for the same rules, never a different rule.

**Caddy.** In `Caddyfile.prod`'s single-page-app block:

- `@landing path / /join/*` → `index.html`; `@auth path /login /login/* /register /forgot /reset/* /verify-email/* /email-change/cancel /oauth/discord/callback` → `auth.html`; `@invite path /invite/* /template/* /no-invitation` → `invite.html`; `@profile path /~*` → `profile.html` (wave 34). Each with the public CSP.
- `@legal path /house-notes` → `reverse_proxy` to `sr-server` (section 7); `@public path /entrance/* /fonts/* /icons/* /sw.js /manifest.webmanifest /offline.html /offline.css /robots.txt /THIRD_PARTY_NOTICES.md` → the file with today's cache headers.
- `handle_errors` serves `404.html` and `50x.html` from the web root (plain HTML).
- Everything else, `/app` and `/app/*` included, is `reverse_proxy` to `sr-server`. `try_files {path} /index.html` goes.

`render-caddyfile.mjs` renders the public CSP line; the app CSP leaves the Caddyfile. `prod.yml` mounts `SR_WEB_DIR` into the server container too (`SR_WEB__ROOT=/srv/web`, read-only); the systemd unit sets `SR_WEB__ROOT`. `INSTALL.md` step 6 and `UPGRADE.md` say so; `sr-cli preflight` gains a row ("web root set and `app.html` present"; warn when unset).

**CSP.** Public shells: `default-src 'self'; script-src 'self'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; manifest-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; report-uri /internal/csp-report; report-to csp-endpoint`. The legal and error pages: the same minus `script-src` and `connect-src` (`default-src 'none'; style-src 'self'; img-src 'self'; font-src 'self'; …`). App shell: today's `buildCsp` output, written by the app build to `dist/app/csp.txt`, sent verbatim by `sr-server`, which refuses to start when `[web] root` is set and the file is missing. `csp.ts` exports all three; `csp.test.ts` pins the Caddyfile lines and `csp.txt`.

**The API's own oracle.** `GET /api/v1/<unknown>` is `404` today while a real route is `401` for an anonymous caller. `build_router`'s `v1` fallback becomes `401` without a principal, `404` with one; `route_matrix` adds both cases.

## 4. Login hand-off and logout purge

**Hand-off.** Every success path (`Login`, `TwoFactor`, `LoginLink`, `DiscordCallback`, `Register` on auto-login, passkey sign-in, `VerifyEmail` when it signs in) calls `enterApp(next?)` in `lib/enterApp.ts`: `location.assign(safeNext(next) ?? '/app')`. `safeNext` is the server's `next` rule (section 3) as a unit-tested function; `next` is written by the server's `302` and read through `validateLoginSearch`. `useRedirectIfLoggedIn` (`/` and `/login`) calls `enterApp()` after a `200` from `GET /users/@me`; it no longer reads `lastSection` or touches a router. `/app` in the app router replaces the history entry with `useUiStore().lastSection` (ENT-UI-023's behaviour); `/` in the app router does the same for an installed app or a bookmark.

**Logout.** `POST /sr/auth/logout` and `logout-all` add `Clear-Site-Data: "cache", "storage"` to the response that clears the cookie: `"cache"` empties the HTTP cache (the `private` app files), `"storage"` empties Cache Storage, IndexedDB, localStorage and unregisters the worker. Dropped with it: the upload ledger (user data, right to drop), the saved language (`accountLocale.ts` restores it at the next sign-in; the public surfaces negotiate from the browser), the dismissed-install flag. Where the header is ignored (WebKit honours part of it), the app's logout posts `{ type: 'PURGE_APP' }` to the worker and awaits `{ type: 'PURGED' }` before calling the API; the worker deletes every `sr-app-*` cache. A session revoked from elsewhere (`logout-all`, staff) cannot send the header here; the next app navigation or chunk fetch gets `302`/`401`, the app unloads to `/login`, and the worker, seeing the `401` on an `/app/` request, deletes the app caches. Until then the files sit in that browser's cache unreadable by any page the server will serve; accepted, as for any cached private response.

**Expiry inside the app.** The API client's `401` handler sends the member out with `location.assign('/login?next=' + current)`, a document navigation into the `auth` surface, never a router transition.

## 5. Service worker and PWA

`public/sw.js` stays one classic script at root scope, registered by the public surfaces and by the app (same module). Changes:

- **Two caches.** `sr-static-<build>` precaches the public shells (`index.html`, `auth.html`, `invite.html`, `profile.html` when it exists, `offline.html`, `404.html`), the public assets they reference (read by `pwaPlugin` from each public shell), the preloaded fonts, `/manifest.webmanifest`, `/offline.css`, `/icons/icon-192.png`. `sr-app-<build>` holds `/app/*` cache-first on first use (`200`, `basic`) and `app.html` as the app's navigation fallback. The worker never requests an `/app/` URL on its own.
- **Navigation.** Network-first as today. A `200 text/html` carrying `id="root"` is stored as the shell of the cache its path belongs to (surface table → `sr-static`, else `sr-app`); the shell-mark rule of RDY-PWA-001 stays. Offline: a public path falls back to its surface's cached shell, then `/offline.html`; any other path to the cached `app.html` if present, else `/offline.html`. The worker's surface table is generated from the same source as Caddy's matchers and `corePaths.ts` (`apps/web/public-surfaces.json`, read by the public Vite config, `pwaPlugin`, `render-caddyfile.mjs` and `web.rs` through the build output `dist/surfaces.json`), pinned by one test.
- **Purge.** Delete every `sr-app-*` cache on `PURGE_APP`, on a `401` or a `302` to `/login` for any `/app/` request or app navigation, and on activation of a new build. Never delete `sr-static-<current>`.
- **No app names.** The worker handles only `GET` requests whose path is a public file, a public surface, `/app/*`, or a navigation; everything else is bypassed by default, so `/api`, `/gateway`, `/cdn`, `/voice`, `/developers`, `/internal` are bypassed without being named (today's `BYPASS_PREFIXES` go). The push handler's default URL becomes `/app`; a payload `url` is accepted only when it starts with `/`.
- **Install prompt (XC-PWA-003).** `PwaHost` lives in the app build; no public surface mounts it, so no visitor is asked to install. `start_url: /app`: with a session the app opens, without one the server's `302` lands on `/login?next=/app`.
- **Manifests.** `/manifest.webmanifest` (public): `start_url: "/app"`, `id: "/"`, `scope: "/"`, icons, `share_target` (its `action: /share` is the Web Share Target contract and names no feature; an anonymous share lands on `/login?next=/share?...`), **no `shortcuts`**. `/app/manifest.webmanifest` (gated, linked by `app.html`): the same plus the shortcuts. Same `id`, so one app. The install exists only in the app, so an installed app has the shortcuts.
- **Update flow (RDY-PWA-001).** One build id over every shell and both precache lists. The toast lives in `PwaHost` (app) and in a small `PublicUpdateToast` (public, `pwa.update.*` keys). `pwa-update.spec.ts` keeps its two-build drill and adds: signed in, build B offered on an app page, accepted, `sr-app-A` gone; anonymous on `/login`, build B offered and accepted, no `sr-app-*` cache at any point. Wave 30's "reload at a track boundary" applies in the app only.
- **Offline page.** `offline.html` stays static, in the entrance palette, naming nothing; `pwa-security.spec.ts` keeps checking it is never stored as a shell.
- P26-PWA-1 (no precache of lazy chunks) holds, now as a privacy rule too. `swFetch.test.ts` gains the new classification cases.

## 7. What stays public, and why

- **The auth API** (`/sr/auth/*` login, 2FA, login link, passkeys, Discord start and callback, forgot, reset, verify-email; `/sr/register`, `/sr/usernames/check`, `/sr/age-gate`, `/sr/csrf`, `/sr/compliance/public`, `/sr/entrance/copy` and the hero image): the surfaces cannot work without them; each answers one question about one account or one code; rate limits as today.
- **The invite and template lookups** (`GET /sr/invites/{code}`, the template lookup): a code is a secret its holder was given; the answer is valid or not. The invite page (D-021) keeps offering nothing to a visitor without an account.

## 8. Enforcement, per surface

**`scripts/check-entrance-isolation.mjs`** (Web job, after the build, beside the bundle budget):

1. Builds the denylist from the app build: every chunk base name in `dist/app/` with the hash stripped; every app route path from `dist/app/routes.json` (written by a Vite plugin that evaluates `routePaths()` exported by `router.tsx`) except `/`, `/app` and `/login`; every operation path from `crates/sr-api/openapi.json` (kept in the tree by `openapi.yml`) whose tag is not `auth`; every message-key prefix of a non-core fragment (`help.`, `lounge.`, `admin.`, `cinema.`, …); and `scripts/entrance-denylist.json`, a hand-kept word list (`Lounge`, `Cinema`, `Library`, `Soundboard`, `Activities`, `Watch Party`, `Staff`, `jukebox`, `MiniPlayer`, `VoiceBridge`, `wasm-unsafe-eval`, `ffmpeg`, `hls`, `jassub`, `/channels`, `/gateway`, `/cdn`, `/voice`, `/developers`, `/help`, …) that a wave adding a feature appends to (roadmap-p27 section 2 names it).
2. For **each public surface** in `dist/surfaces.json`: computes the shell's closure (static imports, as `check-bundle-budget.mjs` does), checks it against that surface's budget, checks that every module in the closure (from the public build's `.vite/manifest.json`) is under that surface's `ALLOWED.ts` list, and scans every file of the closure plus the shell for any denylist token (whole word; case-sensitive for identifiers, case-insensitive for the hand-kept words), any `.map`, any `sourceMappingURL`, any `<link rel="modulepreload"|"preload">` outside `/entrance/` and `/fonts/`, any `import(` outside `/entrance/`, and that no file of the closure is also referenced from `dist/app.html`.
3. Scans the plain-HTML surfaces (`dist/legal/*.html`, `404.html`, `50x.html`, `offline.html`) for any `<script`, any `on*=` attribute, any `fetch`, and the denylist; scans `sw.js`, `manifest.webmanifest`, `offline.css`, `robots.txt`, `THIRD_PARTY_NOTICES.md` for the denylist.
4. Fails naming the surface, the file, the token and the rule that produced it. `scripts/entrance-allow.json` lists tolerated matches with a surface, a token and a reason each; an entry without a reason fails. A surface present in `public-surfaces.json` with no shell in `dist`, or a public shell in `dist` that is not in the table, fails: a new public page cannot appear without joining the table and therefore the check.

**`e2e/tests/entrance-isolation.spec.ts`** (the `playwright` job, Chromium, against `sr-server` serving the dist with `serve_public = true`; also prod-smoke's `stack` job through Caddy). The spec iterates `public-surfaces.json`, so a surface added later is tested without a new spec:

- Anonymous, per surface: open each path of the surface (with a dummy code or token where the path has one), collect every request; assert none is under `/app/`, none is `/app.html`, none is `.wasm`, none is a hashed file outside `/entrance/` and `/fonts/`, and the loaded scripts are a subset of that surface's shell references (no surface loads another surface's chunk unless it is a shared public chunk). For the plain-HTML surfaces assert zero script requests. Then: `GET /channels`, `/admin`, `/help`, `/nonexistent-xyz` and `/app` all `302` to `/login?next=`; `GET /app/anything.js` and `/app/<a real name read from the signed-in run>` both `401`; `GET /api/v1/openapi.json`, `/developers/docs/api`, `/api/v1/nope` are `401`/`302`; `/house-notes` is `200 text/html` with a no-script CSP; the body of each public shell and the sources it loads contain none of ten words from the denylist (a smoke copy; the full check is the script).
- Signed in: sign in through the UI, assert the move to `/app` is a document load (no `pushState`), the app opens, `/app/*` responses carry `Cache-Control: private` and `Vary: Cookie`; log out through the UI, assert `Clear-Site-Data` on the response, no `sr-app-*` cache, and a reload of `/channels` is a `302`.
- Revoked elsewhere: revoke the session through the API from a second context; the next chunk fetch gets `401`, the page lands on `/login`, the app cache is gone.

**`crates/sr-server/tests/web_gate.rs`** (Rust job): a temporary web root with fake shells and assets, `app/csp.txt`, `surfaces.json`, a legal template; the table of section 3 line by line (status, headers, empty body), identical answers for present and absent files, `next` cases (`//evil`, `https://`, a 3 KB path), a bot token refused, a revoked session refused, `serve_public` on and off, the legal page's placeholder substitution and escaping and locale fallback, the start-up refusal when `csp.txt` is missing. `route_matrix.tsv` gains rows for `/app`, `/app/{*path}`, `/api/v1/openapi.json`, `/developers/docs/api` (`session`) and `/house-notes` (`public`); `authz_matrix.rs` runs them.

**Repo checks** (`repo-checks.yml`): each `apps/web/src/public/<surface>/**` imports only from its `ALLOWED.ts` (a Vitest); `src/main.tsx` no longer exists (the entries are `src/public/<surface>/main.tsx` and `src/app/main.tsx`); `public-surfaces.json`, `corePaths.ts`, the Caddyfile matchers and `sw.js`'s table agree (one test reading all four).
