### Rules every wave follows

The rules of [roadmap-p20.md](roadmap-p20.md) section 2 apply unchanged: worktrees `C:\Users\braxt\Desktop\SIDEROOM_wt\p<wave>-<agent>` on `feat/p<wave>-<agent>` with their own `CARGO_TARGET_DIR`, scratch database `sr_p<wave>_<agent>` and ports; one cargo build at a time per agent (`-j 2`); ten migration numbers per agent, unused numbers stay unused; the append-only shared files; generated files regenerated by the integrator; one i18n fragment per agent (`p<wave>-<agent>-<n>.ts`); a handoff `docs/dev/handoff/feat-p<wave>-<agent>.md` with "Resume here"; integration on `integration/phase<wave>` with the full gate list; nothing pushed, merged or downloaded without the owner; proof over claims. Two additions:

- **Standard runners only.** Every new CI step runs on `ubuntu-latest` with what `apt` and the existing workflows already install; no self-hosted runner, no larger runner, no new action from the marketplace.
- **No new dependency.** Neither wave adds a crate, an npm package or a container image. An item that turns out to need one is written so it degrades to a documented manual step and the need is flagged in "Needs the owner".
