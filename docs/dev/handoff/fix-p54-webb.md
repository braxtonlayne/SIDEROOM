  - What existed: `voice/e2ee/verified.ts` kept a verified mark per user *tied to one key* (localStorage), so a new key already showed as unverified, but nothing remembered the first key seen and nothing told the viewer a key had changed. The DAVE-style identity key itself (`identity.ts`) is per device in IndexedDB.
  - New `voice/e2ee/pins.ts`: the first identity key seen per person is pinned in IndexedDB (`sr-e2ee-pins`, keyed `<viewer>:<user>`). `bindToStore` (runtime.ts) checks every roster update; a different key drops the verified mark (old and new key) and lists the person in `keyChanged`. No server part, no setting.
