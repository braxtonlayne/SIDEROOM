## Proposed inventory rows
- SEC-AUD-138: A browser-direct upload never keeps a content type a browser would run: HTML, XHTML, SVG, XML, script and any `text/*` other than plain, VTT and CSV are stored as `application/octet-stream`, so `/cdn/mount` redirects to a bucket that never serves them as a page. D-629.
- SEC-AUD-139: The Activities bundle cleanup lists objects before it reads the live set, and keeps a bundle superseded within 24 hours (`superseded_at`, set by a trigger), so neither a fresh upload nor a bundle members still load is deleted. D-630.
- SEC-AUD-140: A lagged search firehose clears the viewable-channel and NSFW caches, and the feature-settings listener drops its cache on lag, so lost events cannot keep a stale allow-list or flag alive. D-628.
- SEC-AUD-141: The gateway's user and guild pumps use `subscribe_lagging`: a lagged user topic re-checks every session of the user and clears their age and safety caches; a lagged guild topic rebuilds the member lists. D-628.

## Proposed threat-model rows
- Stored active content on the bucket origin (D-629): a member uploads HTML/SVG to a connected bucket and the bucket serves it with that type on its own origin (script on a domain the user trusts). Mitigation: the app stores active types as `application/octet-stream`. Residual: objects stored before this change and objects put into the bucket outside the app keep their type; the presigned-GET response-content-type override is not forced yet.
- Authorization state held by an in-memory queue (extends the wave 60 row, D-628): search and feature caches (viewable channels, NSFW flag, feature flags) and the gateway's user and server topics follow events over bounded broadcast channels. Threat: a dropped event leaves a stale allow-list, flag, or a revoked session connected. Mitigation: lag is surfaced; caches are cleared, sessions re-check, member lists rebuild. Residual: lost dispatches are not replayed (clients may miss a message until they resync); bounded by TTL (60 s) and the 60 s session re-check.
