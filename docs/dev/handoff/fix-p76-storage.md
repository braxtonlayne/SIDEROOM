## The reload finding (299)
`MountsPanel` renders `<li key={m.id}><MountRow .../></li>` and `onChanged` is `res.reload`. The list's reload keeps the same keys, so `MountRow` is not remounted and its local `cors` state survives; but the code does not rely on that: it reads `mount.cors_ok_at` too, which the reloaded mount carries after an Apply or a passed check. Test (a) proves the row stays gone after the reload (waits for the "Ready" badge, which reads the reloaded `cors_ok_at`). A remount would still hide the row. Edge: a Check CORS that answers `missing` is only in local state, so after a full page reload the stored `last_test` row (warn) shows again until the next Test connection; that is the table honestly reporting its own test.
