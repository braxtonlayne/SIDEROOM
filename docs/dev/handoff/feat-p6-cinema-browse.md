## Wire mapping worth knowing (spec section 8)
- `GET /cinema/discover {hero: Row, rows: Row[]}`: hero titles come from `hero.items`; rows keyed by `key`; `display: banner` is the collage, `display: hero` rows are skipped in the list; `explore` (a titles query) becomes the Explore-all link on the matching browse page.
- Browse uses the catalog's own query names (`genres`, `collection`, `year_from/to`, `rating` (content rating), `runtime_max`, `language`, `subtitle_language`, `age`, `sort` = updated|newest|title|year|runtime|curated, cursor paging). The search page uses `GET /cinema/search` (one page of up to 50), since `/titles` has no text query.
- Own state: `GET /cinema/me/list?limit=100` (in-list marks) and `GET /cinema/me/continue-watching` (resume position and episode) are merged into cards, hero and header (`useMy`); episode ticks come from `GET /titles/{id}/watch-state`; watched writes are `POST /titles/{id}/watched {watched, episode_id?|season?}`; rating `PUT /titles/{id}/rating {score}` and mine from `GET .../ratings`.
- Related: there is no related route; "More like this" is a browse of the same kind and first genre, minus the title itself.

## Decisions
- Reviews and comments are in, because the social contract is in the spec. List envelopes are read tolerantly (`items` or `reviews`/`comments`). Authors come back as ids only, so other people show as "A member".
- The saved-list membership is a 100-item fetch (no per-title membership route). Beyond 100 saved titles the "My list" mark can be wrong; ask for a `in_list` field on `Title`/`RowItem` or a membership route.
- i18n: not used (new strings are English literals; the message catalog is typed per key and edits to it conflict across agents). Wrapping them in `useT()` is mechanical later.
- Footer "About this library" and Live TV link point at existing/other pages (`/house-notes`, `/cinema/live-tv`); My list is the player agent's route. Avatar menu items My uploads, Upload, Requests go to the Library's submission pages (`/library/submissions`, `/upload`, `/requests`), the only ones that exist today.
- Plain anchors (not typed `Link`) for nav and watch links so the branch typechecks without the player routes registered.
- `browseSearch.ts` holds the URL-search validator so the router does not pull the Browse page into the entry bundle (entrance stays at ~200 KB gzip).

## Not done / follow-ups
- Trailer playback: the catalog exposes `has_trailer` and trailer assets, not a file URL. The Trailer buttons open `/cinema/watch/{id}?trailer=1` (player agent to handle) unless a `trailer_url` is ever supplied (then a modal `<video>` plays it).
- Watch together (watch parties), Share to Lounge as a message card, Download (CIN-DL), Contributors (CIN-SOC-003): stubs or disabled.
- Reviews and comments: no replies thread UI (`reply_count` is not shown), no edit, report or pagination (first page only).
- No Playwright spec (needs a seeded catalog); coverage is MSW only. Browser-visual check was done by hand with a mock server.
- Mockup detail: the "+" is a hover action on the poster, not always visible next to the title as in `cinema-movies.jpg`; trade-off kept so Discover rows match the spec's hover actions.
