# Handoff: feat/p16-backend (TV-HLS-003, TV-HLS-005, FND-DB-009, DEV-BOT-007)

Base `integration/phase16`. No migrations, no new routes, no OpenAPI change, no web change. No new crates (Cargo.lock only gained dependency edges: `sr-cli` -> `image`, `sr-library`; `sr-sdk` -> `str0m` plus dev-deps `sr-voice`, `sr-voice-proto`, `axum`).

## Done
- **TV-HLS-003 slate.** `sr_tv::live::render_slate_media` loops a configured slate asset on the wall clock (anchored at the epoch, so every client sees the same window; discontinuity + map + PDT at every wrap; sequence numbers start at 2^32 so they never go backwards from a programme). `TvService::with_slate(asset_id)`; wired in `sr-server` from env `SR_TV_SLATE_ASSET`. `live_master` and `live_media` fall back to it on `OffAir` (age gate and unknown channel errors still win); `tune` returns `master_url` for an off-air channel when a slate exists (state stays `off_air`). `sr_transcoder::slate::slate_source_args` builds the ffmpeg `lavfi` command (smptebars or testsrc2 plus a sine tone, no input file). Tests: `live::tests::the_slate_loops_...`, `service_tests::an_off_air_channel_shows_the_slate_instead_of_404`, three args tests.
- **TV-HLS-005.** `crates/sr-tv/tests/hls_sync.rs`: clients with +-1 s skew stay within one segment on video and audio for ten minutes of polling, sequence never moves backwards, discontinuity/map/disc-sequence at a programme boundary. No browser.
- **FND-DB-009.** `sr-cli seed` now also creates three published library series (manga, comic, webtoon) whose pages are drawn in code (CC0, `crates/sr-cli/src/library_seed.rs`), run through the real ingest pipeline (WebP, variants, blurhash) into the bucket, cover set, idempotent by title. Skipped with a message when `storage.endpoint` is `memory:` or the bucket is unreachable. Postgres test `samples_are_seeded_published_and_idempotent` (in-memory storage).
- **DEV-BOT-007.** `sr_sdk::voice_transport` (feature `voice-transport`; `voice-e2ee` and `voice-transport` are now default features, P15-DEV-5): `voice_state_body`, `GatewayHandle::voice_state_update` (op 4 on the guild's shard), `VoiceServerUpdate::from_dispatch`, `VoiceSession` (SFU WebSocket IDENTIFY/READY/heartbeat, str0m session, one send-only audio line, answers the SFU's offers, `send_opus`, `pump` -> `VoiceEvent`), `FrameTransform` (implemented by `E2eeMedia`). In a call declaring E2EE, `send_opus` fails with `EncryptionRequired` without a transform and undecryptable frames are reported, not played. `tests/voice_transport.rs` (5 tests) runs two sessions against the real in-process SFU, including real epoch keys. Example `examples/voice_bot.rs`. Spec 3.13, README and inventory updated.

## Still open (and why)
- **Slate media bytes.** There is no ffmpeg on this machine, so no slate asset was actually encoded. To go live: run `slate_source_args` (smptebars, 12 s) on a machine with ffmpeg, ingest the MP4 as a normal asset through the existing transcode job with 2 s segments in the same rungs as the programmes, then set `SR_TV_SLATE_ASSET=<asset id>`. A CLI wrapper for that is not written. The master offers the slate's own rungs; a client that switches between programme and slate gets a discontinuity but may change rung set.
- **Tune state for slate.** I kept `state: off_air` (guide semantics) and only added `master_url`; the web player does not use `master_url` while off air. Whether the player should play the slate is a product call (owner question 1).
- **TV-HLS-005 Safari** itself (real device) is the e2e agent's / manual.
- **DEV-BOT-007 leftovers:** TypeScript SDK voice, reconnect/resume of the SFU socket, Opus encode/decode (bot supplies frames), a live run against a real server (the example compiles; the SFU round trip is tested in-process only), ICE-TCP/TURN.
- **FND-DB-009:** Cinema/video samples are not seeded (they need a transcode run). Library search is indexed on the next server start (`reindex_all`).

## Decisions / owner questions
Answered 2026-10-19 as P16-BE-1 to P16-BE-4 in `docs/open-question-answers.md` (D-266 to D-269; follow-ups L-10 to L-15 in `docs/dev/answers-followups-p16.md`): the player plays the slate (`Tune.slate`), the 2^32 offset is replaced by chaining the slate into the channel's numbering, the SDK defaults stay, and `sr-cli tv slate` makes and registers the asset on the transcoder host.

1. Should the web player play the slate while a channel is off air (needs `state` or a new `slate` flag in `Tune`, plus OpenAPI)? Default kept: no.
2. Slate sequence numbers use a 2^32 offset so they stay above wall-clock-seeded programme numbers; returning to a programme drops back (a discontinuity precedes it). OK, or should programme seeding move above it?
3. `voice-e2ee`/`voice-transport` are default features of `sr-sdk` now (per P15-DEV-5); bots that do not want openmls/str0m must use `default-features = false`.
