## 1. SEC-AUD-194: the feed channels (D-667)
- `STAFF_CHANNELS` now lives in `crates/sr-server/src/staff_feed.rs` (a `pub const` of six names: `staff-announcements`, `review-queue`, `alerts`, `ops`, `new-members`, `donations`). `sr-cli` depends on `sr-server`, so it imports the list: the bootstrap and the start-up repair read one list. `#alerts` has no permission overwrites (the bootstrap passes `&[]`), so the two new channels have none either: **whoever is a member of the Staff Server can read `#new-members` and `#donations`**, exactly as `#alerts`. Only appointed staff are members; the system user posts.
- Start-up repair: `StaffVoice::ensure_channels` runs inside `ensure_member` (once per process, and only once a Staff Server exists). The server's start calls `ensure_crash_channel` (`app.rs:1514`), which calls `ensure_member`, so the repair runs at start without touching `app.rs`. It creates each missing name as a text channel in the "Text Channels" category after the last text channel, through `PgChatRepo::insert_channel` (the same repository call the bootstrap uses), one `info` log per channel. I did not move the bootstrap's `add_text_channel` into a shared crate: both call the same repository method with no overwrites, and `the_bootstrap_creates_the_feed_channels` checks that the bootstrap makes every name of the shared list.
- **Two nodes starting together:** the check and the inserts are one transaction holding `pg_advisory_xact_lock(hashtextextended('staff-feed-channels:<guild id>', 0))`. The second node waits, then finds the channels the first made and creates nothing. There is no unique index on channel names, hence a lock rather than a constraint. `a_staff_server_without_them_gets_them_at_start_once` runs two calls concurrently on one pool and checks that together they create exactly two channels.
- A channel an operator deleted on purpose comes back at the next start: said in `docs/07` and `docs/specs/admin-staff-server.md`. No Staff Server: nothing happens, no error.
- Docs: `docs/07` (channel list), `docs/specs/admin-staff-server.md` (section 3; the two rows are now "seeded"). `deploy/GO-LIVE.md` does not list the channels: no change.
